# 6. Skittle を番号を持つオブジェクトとして設計する

日付: 2026-11-21

## ステータス

承認済み

## コンテキスト

お題(STEP 01-1)では、スキットルは 1〜12 の番号を持ち、各番号1本ずつ存在する。スキットル番号と点数がともに `number` だと取り違えやすい。範囲外の番号の扱いは、お題では決まっておらず、ペアで決めてテストに残す必要がある。

## 決定

- `SkittleNumber` を 1〜12 のリテラル union とする。
- `Skittle` を `{ readonly number: SkittleNumber }` というオブジェクトとする。
- 範囲外の番号(0、13 など)は `SkittleNumber` の型で防ぎ、ランタイム検証は持たない。この決定は `@ts-expect-error` を使ったテストで残す。
- 生成用のヘルパー関数は作らない。必要になった時点で追加する。
- 配置は `src/skittle.ts` とする。

## 結果

- スキットルと点数が型の上で区別され、取り違えがコンパイル時に検出される。
- 範囲外の番号は `tsc` が検出する。実行時には検証しないため、外部入力を受ける境界ができたら、`number` から `Skittle` への変換を別途設計する。
- テストでは `{ number: 5 }` のようにリテラルを直接書く。
