# 15. Property-based Testing を fast-check で導入する

日付: 2026-11-25

## ステータス

承認済み

## コンテキスト

例示ベースのテストは、書いた例しか確かめられない。このプロジェクトのドメインには、`scoreOf` は投てきの連結に対して加法的、`scoreHistoryOf` の最後の要素は `scoreOf` と一致する、など、入力によらず成り立つ性質が多い。また、入力空間(1〜12 の番号、最大12本の投てき)が小さく、有効な入力の生成器(arbitrary)を書きやすい。

## 検討した選択肢

- **fast-check**: TypeScript の型を持ち、依存がなく、テストランナーに依存しない。`node:test` の中から `fc.assert(fc.property(...))` を呼べる。採用する。
- **自前の乱数テスト**: 縮小(shrinking)や再現用の seed がなく、失敗した入力を絞り込めない。採用しない。

## 決定

- `fast-check` を devDependencies に追加する。
- プロパティのテストは例示のテストと分け、`src/__tests__/molkky.property.test.ts` に置く。`src/**/*.test.ts` に一致するため、既存の `npm test` などにそのまま含まれる。
- 入力の生成器は、ドメインの不変条件を満たすように作る。
  - スキットルは `skittleOf` で作る。
  - 1回の投てきは `fc.uniqueArray` で、番号が重複しないものにする。
- 確かめる性質:
  - `skittleOf`: 1〜12 の整数なら番号が一致する。範囲外の整数と整数でない数は表明で落ちる。
  - `pointsOf`: 1本なら番号、0本・2本以上なら本数。点数は 0〜12。順序に依存しない。重複があれば表明で落ちる。
  - `scoreOf`: 空なら0。連結が和になる。順序に依存しない。単調に増える。
  - `scoreHistoryOf`: 要素数が投てきの回数に一致する。最後の要素が `scoreOf` に一致する。i 番目が先頭から i 回目までの `scoreOf` に一致する。減らない。
- 並べ替えのテストには、`fc.shuffledSubarray` を使わない。これは順序を保った部分列を返すだけで、順列にならない。乱数のキーで整列する `permutationOf` を、テスト内で用意する。
- 例示のテストは残す。仕様書の例(お題の例)と、エラーメッセージの確認は、例示のテストが担う。

## 結果

- Stryker をプロパティのテストだけで走らせると、33 個のミュータントのうち 31 個を倒せる。残るのは、エラーメッセージの文字列を変えた 2 個で、これは例示のテストで倒している。全テストでは mutation score 100% を保つ。
- プロパティのテストは入力を 100 回ずつ生成するため、`npm test` の実行時間が少し増える。
- 失敗した場合、fast-check が反例を縮小して seed とともに報告する。
