# 9. 重複したスキットルは想定外として実行時アサーションで落とす

日付: 2026-11-22

## ステータス

承認済み

## コンテキスト

各番号のスキットルは1本ずつしかないため、同じ番号のスキットルが1回の投てきに2本含まれることは現実にはありえない。お題はこの入力の扱いを定めていないため、ペアで決めてテストに残す。

## 検討した選択肢

- **型で弾く**: `const` ジェネリクスと条件型でタプルの重複を判定する試作を行った。リテラルを直書きしたタプルだけが対象で、`Skittle` 型の変数どうし(例: `[s, s]`)は値が異なっても偽陽性になり、動的な配列は素通りする。エラーメッセージも `never` になり原因が分からない。実用にならない。
- **検証せずに数える**: `[5, 5]` を2点とする。想定外の入力を黙って受け入れる。
- **構造で防ぐ**: `Throw` を `ReadonlySet<SkittleNumber>` にする。`Skittle` オブジェクトの設計(ADR 0006)と合わない。また `Set<Skittle>` は参照同一性で比較するため、重複排除にならない。
- **実行時のアサーションで落とす**: 採用。

## 決定

同じ `number` のスキットルが `Throw` に2本以上含まれる場合は想定外とし、`pointsOf` が `node:assert` のアサーションで落とす。例外の捕捉や `Result` による表現は行わない。

## 結果

- 前提違反が黙って通らず、早期に発見できる。
- 型では防げないため、実行時にしか検出されない。
- 重複を許容する、またはエラーを値で返すといった仕様が出た場合は、新しい ADR で見直す。
